## 1. Dock balloons to full width, then snaps — Critical (my regression)

**Seen:** measured every frame while wheel-scrolling on `/clips` at 1366×649:

| time    | dock width  | state    |
| ------- | ----------- | -------- |
| 0 ms    | 1017 px     | expanded |
| 70 ms   | **1342 px** | compact  |
| 412 ms  | 365 px      | compact  |
| 2061 ms | **1065 px** | expanded |
| 2412 ms | 1017 px     | expanded |

So on every shrink the dock first stretches across the whole screen for ~⅓ s and then collapses, and
on every expand it overshoots by ~50 px and then settles. This is the "it got worse".

**Cause:** commit `7aeefcc` (fix #6) gave the dock labels `transition: display … allow-discrete` so
they could fade. With `allow-discrete`, an element switching to `display: none` keeps its box until
the transition ends. Meanwhile the compact rules already switched the chips to a row layout, so the
still-present JA + EN labels sit side by side → the dock is at its widest in the middle of shrinking.

**Fix:**

- Remove the `display … allow-discrete` transition and the `@starting-style` block from `motion.css`.
- Animate the size change in one place instead: keep the labels in the layout and collapse them
  with `max-width`/`opacity` (or `grid-template-rows: 0fr`), or animate the dock's own width with a
  measured FLIP (as the filter bars do), so the outline and the contents move together.
- Add a regression test: sample the dock width for 1 s after a scroll and assert it never exceeds the
  expanded width and changes monotonically.

## 2. Filter bars stay docked over the footer — High

**Seen:** after scrolling to the very bottom of the page, the bar is still pinned at the top
(`docked: true`) on all three pages, sitting over the next-chapter cards and the footer:
`/streaming` bar bottom 102 px with the footer starting at 120 px; `/discography` 62 / 121; `/arts`
65 / 120.

**Cause:** `topbar.ts` only checks "has the slot's top passed the top of the screen". It never checks
whether the section the bar filters has ended.

**Fix:** observe the bar's section too. Dock only while the slot's top is above the top edge **and**
the section's bottom is still below the bar's height; undock (slide back) once the section has
scrolled past. Use one `IntersectionObserver` with two sentinels (slot top, section end) instead of a
scroll listener, which also removes the per-scroll `getBoundingClientRect`.

## 3. Too many dock behaviours — High (consistency)

**Seen / code:** the dock has three scroll states (expanded, compact, peek), each with its own rules
(top of page, pointer on it, keyboard focus, 2 s idle, scroll direction, fling speed, long-page list,
"quiet" windows after page changes and anchors). Phones add a fourth layout (five chips + More + ⚙)
that also compacts. Each rule is reasonable alone; together the outcome depends on speed, timing and
page, which is why it feels unpredictable.

**Fix — make it one simple, predictable rule set:**

1. **Remove peek entirely** (and `LONG_PAGES`, the velocity check, the peek CSS).
2. Two states only: **expanded** at the top of the page and whenever you scroll **up**; **compact**
   while you scroll **down** past the first screen. Nothing else changes the state except: pointer on
   the dock or keyboard focus inside it → expanded.
3. Drop the 2-second idle re-expand (it makes the dock grow while you're reading, under the cursor).
   Scrolling up is the way to get it back, like most sites.
4. Apply the same two states on phones.
5. One transition for the change (see #1), one duration, no per-part timings.

## 4. Peek leaves the chapter plate sticking up — High

**Seen:** after a fast fling on `/streaming`: `state=peek`, `.dock__plate` still displayed, its top at
626 px of a 649 px window. On phones the pink "NO.04 · STREAM" tab sits alone at the bottom edge on
every peeked frame (Streaming, Arts, Messages scroll-throughs).

**Cause:** the plate is hidden in compact (`display:none`) but not in peek, and it's positioned above
the dock (`top: -17px`), so it stays on screen when the dock slides down.

**Fix:** goes away with #3 (no peek). If peek is kept, hide the plate in peek too.

## 5. Off-screen pausing freezes one-shot animations — High

**Code:** `offscreen.ts` marks zones scrolled out of view with `[data-offscreen]`, and `motion.css`
pauses **every** animation inside: `[data-offscreen] * { animation-play-state: paused !important }`.
That includes one-shot entrances (`enter-up`, `enter-pop`, `enter-down`) and scroll reveals, which use
a backwards fill: paused at the start they stay at **opacity 0**.

**Effect:** whenever a page is entered scrolled down (Back/Forward restores the position, `#art=`
links, in-page anchors) the header's entrance is frozen invisible. It only plays, late, when you scroll
back up, so the header "pops in" long after the page loaded. The same can freeze the farewell section
and the stamps.

**Fix:** pause only the infinite loops. Give looping animations a class or attribute (`.loop`, or list
them: stamp ring, marquee, hero ring/bob/bubbles, fx floats, wiggle, dot pulse, eq bars) and scope the
rule to `[data-offscreen] :is(.loop…)`. Never pause entrance/reveal keyframes.

## 6. Scroll reveal leaves empty gaps — Medium

**Seen:** on `/arts`, 400 ms after arriving at a section, 7 tiles on screen were still waiting to
reveal, so the gallery shows large empty areas; the scroll-through frames show the same at
Clips and Discography. With 190 art tiles the stagger (up to 8 × 80 ms + 820 ms) is long enough to see
holes during normal scrolling.

**Fix:** reveal **sections and headings**, not every tile. Remove `.art-tile`, `.clip`, `.jacket`,
`.spread__item`, `.trophy`, `.ribbon-tag` from the reveal list (they already have hover motion), or
reveal a grid as one unit. Shorten the reveal to ~500 ms with a stagger cap of ~240 ms, and start it
earlier (`rootMargin: 0px 0px 15% 0px`) so it finishes as content arrives, not after.

## 7. Filter bars are inconsistent with each other — Medium (consistency)

**Seen:** docked at 1366, the Arts bar is one slim row, Discography is two columns (tabs + tools), and
Streaming is up to three rows (years, search/sort/view, tags) and covers ~100 px of the list. On phones
Streaming's docked bar is three sideways-scrolling rows.

**Fix:** define one docked bar pattern for all three:

- **Desktop:** one row, ≤ 56 px tall. The primary control (tabs / years / sections) scrolls sideways
  with a fade at the edges; secondary controls (search, sort, view) collapse to icon buttons that open
  a small popover. Streaming's tag chips move into that popover when docked.
- **Phone:** the same single row plus one "Filters" button.
- Same height, radius, shadow, padding and slide animation for all three, sharing one CSS class
  (`.topbar`) instead of three sets of rules.

## 8. Pages wider than the phone screen — High (phone)

**Seen:** sideways scroll on phones.

| Page           | Page width on a 390 px phone | Source                                                                                                                         |
| -------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `/discography` | 473 px                       | the hero vinyl `.record__disc` (right edge at 437–481 px)                                                                      |
| `/credits`     | 523 px                       | the content column is ~507 px, forced by its widest child, so the headings, paragraphs and lists inside it also run off screen |

On Discography the dock is also stretched to the page width (464 px), so its right side is off screen.
At 1366 in English, Discography is 2 px too wide (1368 px), from the same vinyl.

**Fix:**

- Discography: clip the hero visual (`.page-head__visual { overflow: clip }`, or `overflow-x: clip` on
  `.page-head`), and size the vinyl with `min(…, 100%)`.
- Credits: find the min-content source (most likely the art-credit tables inside the collapsed
  `<details>`, or a long unbroken credit string). Give the grid/flex items `min-width: 0`, wrap the
  tables in `.table-scroll { overflow-x: auto }`, and add `overflow-wrap: anywhere` to the credit
  lists.
- Add a guard test: on every page at 390 px, `scrollWidth === clientWidth`.

## 9. First screen: the dock covers the first section — Medium

**Seen** at load, with the dock expanded:

| Screen   | What the dock covers                                                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1366×649 | Clips heading "01 Most-viewed clips"; Streaming "Records"; the whole Arts tab bar and the copyright line; a Credits link                                             |
| 1920×953 | About "Profile"; the first row of Clips cards; Discography's result count and first jackets; Streaming record titles; Credits "Artwork" heading; a Privacy paragraph |

Page headers have different heights, so where the first section lands differs per page and screen.

**Fix:** give every page header the same rule, so the first section always starts **above** the dock
or clearly below the fold, never under it:

- `.page-head { min-height: calc(100dvh - var(--dock-reserve)) }` with the content centred, on
  screens taller than ~600 px; or a fixed bottom padding of `var(--dock-reserve)` after the header.
- Arts: put the copyright note after the tab bar, and keep the tab bar out of the dock zone.

## 10. Docked bar on phones: cut-off button, logo disappears — Medium

**Seen:** on a phone, Discography's docked bar cuts the "TIMELINE" button ("TIMELIN"). The logo tab is
hidden whenever a bar is docked (`html.has-topbar .logo-tab { opacity: 0 }`), but stays visible on
every other page, so the top-left corner changes from page to page.

**Fix:** with the single-row pattern from #7, the view toggle becomes an icon button and fits. Keep
the logo visible on phones and dock the bar under it (top: logo height + 8 px) instead of hiding it.

## 11. Dock language in English mode — decision needed

The full dock always shows the Japanese chapter name with the English one under it (it was designed
bilingual). The compact dock now follows the language setting, so the two states disagree.

**Options:** (a) keep both languages everywhere (revert the compact change); or (b) follow the
language setting in both states: English mode shows `HOME` / `ABOUT` big with no Japanese, Japanese
mode shows `ホーム` big with `HOME` small. **Recommendation: (b)**, and apply it the same way to the
chapter sheet, tooltips, related-chapter cards and the footer list, which today show both.

## 12. Inconsistent small label sizes — Medium (consistency)

**Seen:** the uppercase English sub-labels use 8.5 px (sys buttons), 9 px (art tabs, relationship
map, events "PORT"), 9.5 px (dock, disco tabs, event types), 10 px (Talk buttons, clip tags) and 11 px
(dock plate), with different letter-spacing for each. Everything at 9 px or below is hard to read on
the 1366 laptop.

**Fix:** two label tokens in `tokens.css`, `--label-s: 10px / 0.16em` and `--label-m: 11px / 0.2em`,
and use only those for every small uppercase label. Nothing below 10 px.

## 13. Phone tooltips off screen — Low

**Seen:** `.chap__tip` sits at x = −15 px on phones (first chip) on every page.

**Fix:** don't show chapter tooltips on touch/coarse pointers
(`@media (hover: none) { .chap__tip { display: none } }`); on desktop clamp the first and last
tooltip to the dock edges.

## 14. Arts docked tab strip edges — Low

**Seen:** at 1366 the docked strip shows a stray count bubble ("28") at its left edge where the
previous tab is cut, right next to the logo.

**Fix:** a `mask-image` fade on both ends of every sideways strip (the same in all three bars), plus
`scroll-padding-inline` so the current tab never lands under the edge.

## 15. First-visit dock hint over content — Low

**Seen:** the "Choose a chapter ⚓" sticker floats over the gallery above the dock on a first visit,
while the tour is also introducing the dock.

**Fix:** drop the hint. The tour already covers the dock, and the hint flag is set when the tour ends.

## 16. Entrances start late on heavy pages — Low (smoothness)

**Seen:** Streaming (~0.5 MB of HTML), Arts and Discography parse for long enough that the header has
already painted before its entrance animation starts, so text shows, disappears and animates in.

**Fix:** start entrances only once the page has rendered (add `html[data-ready]` after the first
`requestAnimationFrame` following `astro:page-load`), or skip the entrance when the page took more
than ~400 ms to become ready.

## Code-level notes (not visible yet, but worth fixing with the above)

- **Two scroll listeners decide chrome state independently** (`Dock.tsx` and `topbar.ts`, plus
  `LogoTab` at 120 px), each with its own thresholds. Move all chrome state to one small module
  (`chrome-scroll.ts`) that computes `{ atTop, direction, inSection }` once per frame and sets
  attributes on `<html>` (`data-dock`, `data-topbar`, `data-logo`). CSS reacts to those. One source of
  truth → consistent behaviour.
- **`quiet()` windows are guesses** (600 / 900 / 1500 ms). With the simpler rules in #3 they're no
  longer needed: page changes and Back set `atTop`/direction from the new position directly.
- **`view-transition-name: dock` / `logo-tab`** stays, with no morph (from `7aeefcc`), so persistent
  chrome doesn't wipe with the page. Keep it.
- **Reveal and the tour both scroll and measure**; the tour scrolls with `scrollIntoView`, which the
  dock sees as user scrolling. With the attribute module, the tour sets `data-dock="expanded"` while
  it runs instead of the `aia:dock-hold` event.
- **Test coverage:** add e2e checks for #1 (dock width monotonic), #2 (bar undocked at page bottom),
  #8 (no sideways scroll at 390 px on every page) and #9 (first section not under the dock at 1366 and
  1920), so these can't come back.
